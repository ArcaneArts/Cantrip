# Cantrip Wide QA campaign — 2026-10-08

All 394 cases in [WQA.md](WQA.md) have a recorded disposition: **144 PASS, 44 FAIL, 202 BLOCKED, 4 NOT APPLICABLE, 0 NOT RUN**. The campaign is complete as an accounting and issue-filing pass; the blocked coverage remains unverified. This is not a release-readiness certification.

## Environment and method

The browser was the real Cantrip client, connected to the existing native installation and Local Worker. Existing recovery, providers, models and settings were retained. Tested on macOS 27.0.1 arm64 with Codex CLI 0.160.1 and Codex in-app Chromium. The native server/worker were 1.1.2044.

Earlier cases used source b8304277bee8fc57d720de6835ce1179cebeae4b / main 0116c9df333f55ede56bc23abbf14340a3eca7d4 (frontend 1.1.2060). Later cases used the matching release 1.1.2044 frontend at 4e897b1f8327a6d1843909c5e8bd03f472c6a40d. The per-case ledger distinguishes these environments; outcomes do not certify every assertion against the latest application revision.

Tested actions used the browser. Shell commands prepared owned fixtures, managed owned services, collected bounded diagnostics and verified effects. Model turns, GitHub actions, runs, file operations and history were exercised through normal application flows. No application fixes were implemented.

## Skipped coverage and observations not filed

BLOCKED cases preserve the assertion that could not run and any successful partial checks. The most common constraints were:

- Restart, revocation and recovery scenarios that would disrupt the user-owned native server/worker; no isolated equivalent stack was available.
- Code workbench renderer crashes or unavailable Code input/tunnel behavior. Concrete defects were filed where reproducible; dependent assertions stayed blocked.
- A second worker, remote topology, distinct native platform/profile or external history installation was unavailable.
- Valid negative-auth/account fixtures, OAuth interaction, Computer Use action-time confirmation and certain OS/device permissions were unavailable.
- Browser drag/pointer, viewport/device emulation and isolated browser custody limitations prevented specific assertions.
- Newer frontend/server protocol mismatches, unstable terminal attachment, pending native handoff operations and missing optional Java tooling blocked individual cases.

The full local ledger records each blocked ID and reason. Missing hardware, optional tools, credentials, denied permissions and browser-driver limits were not filed as application defects. Uncertain click races and asynchronous loading observations without a concrete contradicted contract were retained as notes. Native transfer rejection remained a bounded blocker; no speculative pending-operation ticket was filed. Literal canary/secret scans are scoped evidence, not a general cryptographic or confidentiality proof.
